а то - из самого первого задания блока (https://github.com/netology-code/jd-homeworks/blob/master/sql-basic/task/README.md). 
А там в табличке нету числового идентификатора по условию, а первичный ключ - совокупность name + surname + age. 
Объект, олицетворяющий первичный ключ (допустим - Human) - не является @Entity, он @Embeddable.
Таким образом, мы не можем объявить репозиторий, работающий с объектом Human - у него вообще нету идентификатора. 
И работать с Human кастомными методами-запросами без анотации @Query мы не можем (а в задании 2 поиска их трёх - именно по полям Human, а не Person).
Я пытался задавать имена кастомным методам-запросам с полями из Human - не запускается, ибо у @Entity Person нету полей name, surname и age - они есть у Human.
Наличие второго задания со звёздочкой @Query* (https://github.com/netology-code/jd-homeworks/blob/master/spring-jpa/task2/README.md) намекает нам на то, что в первом задании использовать @Query нельзя.

Или надо было явно в задании прописать, что можно таблицу переделать под числовой идентификатор - первичный ключ, или выбрасывать из условий задачи поиск по имени-фамилии и возрасту. По логике занятия - логичнее первое.

Вывод - в рамках первого задания мы можем реализовать только поиск по городу, как в самой первой домашке блока.

Я реализовал в этом проекте только то, что считал возможным - а именно - поиск по городу. Причём имя города надо угадать прям как в таблице, ибо не мы реализуем SQL запрос и не можем применить toLowerCase()к значению, полученному из БД.
